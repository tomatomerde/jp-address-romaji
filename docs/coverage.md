# Romanization coverage

Generated by `scripts/measure-coverage.ts`. Regenerate with:

```sh
npx tsx packages/data/src/build-data.ts --out ./address-data
npx tsx scripts/measure-coverage.ts --data ./address-data \
  --figures-out docs/measurements/figures.json > docs/coverage.md
```

**The published coverage and ambiguity figures come from here.** The README, README.ja,
CLAUDE.md and `fromRomaji`'s API docs quote these numbers, and
`scripts/check-quoted-figures.ts` fails CI when one of them stops matching. The koaza
and reading-plausibility figures are a separate report (`scripts/verify-data-assumptions.ts`),
which is run but not checked. Do not edit this file by hand — regenerate it.

Measured on **2026-08-18**, against the dataset fetched that day
(`meta.updated` in `ja.json`). The date moves on every refresh, so this report is
committed monthly whether or not a number moved — that commit is the evidence.

A town is counted as **usable** when the dataset carries either a valid romaji
field or a kana reading. Entries whose romaji collapsed to a bare number are
counted as unusable, matching what the library does at runtime.

## Ambiguity

Measured with the matcher's own key functions (`candidateKeys`, `exactKeys`,
`isPlausibleReading`), so these move when the matcher moves. A *town* here is one
distinct `oaza_cho` name within one municipality — chome rows of the same name are
one town, and rows the matcher skips are skipped here too.

| Metric | Count | Share |
| --- | ---: | ---: |
| Distinct towns | 127800 | 100% |
| **Towns whose full-form romanization is unique within their municipality** | 125178 | **97.95%** |
| Towns involved in a full-form collision | 2622 | 2.05% |
| **Full-form keys matching 2+ towns in one municipality** | 1406 of 211041 | **0.67%** |
| All indexed keys (incl. stemmed short forms) matching 2+ towns | 2780 of 259703 | 1.07% |
| Towns involved in a collision on any indexed key | 4871 | 3.81% |
| **Towns whose full-form romanization is unique nationally** | 76575 | **59.92%** |

The last row is the same keys pooled across the whole country, with no municipality
known — the gap between it and the first row is the whole reason `fromRomaji`
resolves the prefecture and the municipality before it looks at a town name.

The two key rows answer different questions. **All indexed keys** includes the
stemmed short forms `candidateKeys` indexes (`Showa` for 昭和町), so it is the
ambiguity a typed query can actually hit; `fromRomaji` returns `AMBIGUOUS` with the
candidates for those. **Full-form keys** excludes the stems, so it is the residue
that writing the full town name cannot resolve (夷町 and 恵比須町, both `Ebisucho`) —
the figure the decision not to bundle a postal dataset rests on.

## Municipality names shared across prefectures

Why `fromRomaji` resolves the prefecture before anything else. Counted from the
prefecture index only, in the spellings `matchMunicipality` accepts: a ward needs
both segments (`Chuo-ku, Sapporo-shi`), anything else is matched by its own name,
and a county-bearing town may also be written with its county. Two municipalities
in the **same** prefecture that romanize alike are excluded — real ambiguity, but
not something resolving the prefecture first could ever have fixed.

| Metric | Count |
| --- | ---: |
| Municipality records | 1898 |
| **Groups of municipalities in 2+ prefectures sharing a romanization** | **39** |
| ...of those groups, also the same name in Japanese | 19 |
| Municipalities involved | 86 |
| Spellings those groups are indexed under | 56 of 4331 |
| Spellings shared once the administrative suffix is stemmed off | 176 |
| Municipalities involved, stem-inclusive | 243 |

A **group** is a set of municipalities connected by "shares at least one spelling",
not a spelling and not a distinct owner set. One name is usually indexed under more
than one accepted spelling (`Mihama-cho` and the passport-style `Mihama-choh` are the
same four towns), so counting spellings would measure how many long-vowel conventions
the matcher accepts rather than how much ambiguity there is — and counting owner sets
has the same problem once removed (`Konan-shi` is 江南市/湖南市/香南市 while
`Kohnan-shi` is only 江南市/香南市; all three can be confused with one another, so that
is one collision, not two). The stem-inclusive row is wider still, and not the headline
either: stemming folds together names that are not the same name (府中市 and 府中町 both
reduce to `Fuchu`).

"The same name in Japanese" compares the municipality's own name, not its county:
宮城県遠田郡美里町 and 埼玉県児玉郡美里町 are both 美里町. **This is a different quantity
from the group count** — do not read the headline as "N municipalities share a name".
